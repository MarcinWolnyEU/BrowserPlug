    Local file (file://) reading

    …
    Checking…

    The browser doesn't let an extension open a file:// URL itself. To work with a local file, you open it (paste file:///… in the address bar, or Ctrl+O). BrowserPlug can then read that tab.

    Firefox for Android cannot open file:// at all, not just for extensions. Typing file:/// in its address bar does nothing; the capability was dropped in the Fenix rewrite and has not come back (Bugzilla 1806171, open since 2022). So there is no tab for BrowserPlug to read and nothing to turn on: the desktop permission lives in about:addons ▸ Permissions, a page Firefox for Android does not have either. There is no workaround on the phone; use a desktop browser for local files.

    Risk: while reading is enabled, any MCP client connected to BrowserPlug can read the contents of local files you open (and a page opened from file:// can reach other local files).

    To enable reading: open about:addons ▸ BrowserPlug ▸ Permissions and turn on “Access local files on your computer” (Firefox 153+), then Re-check.

    To enable reading: go to the extensions page, turn on Allow access to file URLs, then Re-check.

    SOCKS proxy routing (.onion / Tor)

    …
    Checking…

    Lets BrowserPlug route a tab's traffic, including DNS, through a SOCKS proxy you specify (e.g. socks5://127.0.0.1:9050) instead of a direct connection. Because names are resolved at the proxy, the notable use case is opening Tor .onion hidden services through a Tor SOCKS5 proxy, with no local DNS leak. Routing is fail-closed: if the proxy is unreachable the tab errors instead of falling back to a direct connection.

    Supported: SOCKS5 (socks5://, socks5h://) and SOCKS4 (socks4://, socks4a://) proxies, given as host:port.
    Not supported: HTTP/HTTPS proxies, PAC / auto-config scripts, proxies that require a username/password, and your operating system's own proxy settings.

    Risk: while enabled, any MCP client connected to BrowserPlug can route your browsing (including pages you're logged into) through any SOCKS proxy it names.

    Chrome, Edge and Brave: these browsers cannot route a single tab, so a request that names a proxy switches the entire browser, every tab including the ones you are using, until the agent switches it off. BrowserPlug also switches it off by itself when it loses its connection to the server or the browser restarts, and the agent is told each time it happens.

    Chrome cannot ask for this as an optional permission, so this switch is your consent: while it is off, BrowserPlug refuses every proxy request. Press Allow the browser-wide proxy below to turn it on, and the same button turns it off again (which also ends a proxy that is running).

    To enable routing: open about:addons ▸ BrowserPlug ▸ Permissions and turn on “Control browser proxy settings”, then Re-check.

    Routing itself works on Android; it is the granting that differs. There is no about:addons to flip a toggle in, so ask Firefox for the permission directly with the button below; it must be a real tap, because Firefox only accepts the request from one.

    Allow user scripts (page_eval)

    …
    Checking…

    Running JavaScript in a page (page_eval, and wait conditions that evaluate an expression) goes through Chrome's User Scripts API, which stays locked until you turn on Allow user scripts for this extension. Only you can turn it on; the extension cannot. Every other tool works without it.

    Risk: while it is on, any MCP client connected to BrowserPlug can run any JavaScript in the pages you have open, including the ones you are logged into.

    To enable it: go to the extensions page, turn on Allow user scripts, then Re-check.
